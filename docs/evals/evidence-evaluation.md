# Evidence and answer evaluation

Evaluation repair precedes retrieval changes. Original results, independent adjudications,
release gates and fixture labels remain separate and immutable.

## Judge contract

`brainkit.answer_eval.prepare` supplies the question's own time, the reference rubric,
the answer, and the full **reader-visible** context of each citation. It does not supply
method identity, previous verdicts, hidden candidates or retrieval labels. Every quote
must occur in its own visible source. An id appearing in a packet is not evidence that
the reader saw the full note.

Correctness and support are separate. A supported incomplete total or safe abstention
can still be incorrect; a reference-matching guess can still be unsupported. Historical
questions ask for the historical state. Speaker labels, source dates and surrounding
context matter. Invalid or missing verdicts stay in the denominator.

`python scripts/prepare_answer_eval.py input.json new-output.json` freezes judge inputs
and hashes without calling a provider or overwriting an existing result. A caller must
record exactly what its reader received. This contract does not make an LLM judge an
independent human adjudicator.

## Conversation fixtures

`brainkit.conversation_eval.convert` keeps complete attributed turns and timestamps,
uses neutral occurrence/turn ids, and puts answer annotations in a separate label object.
Duplicate session names do not collapse distinct occurrences. Missing labels remain
visible diagnostics; malformed alignment, dates and missing answer sessions fail.
Existing historical fixtures and scores are not regenerated by this adapter.

## Validation discipline

Use already exposed cases for regression only. Freeze fresh case ids, exclusions,
dataset hashes, model version, prompts and budgets before inspecting outcomes. Compare
the same reader, source representation, evidence limit and rubric. Record first responses
including failures. Report retrieval, answer correctness and supported correctness
separately, with paired uncertainty and per-Brain regressions. Do not revise thresholds
or labels to recover a score.

## What Basic Memory's results establish

Its [published matrix](https://github.com/basicmachines-co/basic-memory/blob/a72751c5d626380dedeed30f55f7a80ba3dc710d/benchmarks/benchmarks/results/matrix-v2-summary.md)
reports 58.3% answer accuracy and 95.1% retrieval recall on its 60-case LongMemEval sample.
It uses Haiku 4.5 as answerer and Sonnet 4.6 as judge. This is not a matched comparison
with our 32-case Haiku 5.5 experiment. Its report identifies answering and presentation
failures even when gold evidence is retrieved.

Its [semantic search design](https://docs.basicmemory.com/concepts/semantic-search)
indexes smaller passages, returns matching text, and offers follow-up reads. These are
useful evidence-delivery mechanisms to test under our unchanged budgets. Copying a
published score, changing the evaluator, or widening the context would not demonstrate
a retrieval improvement. The same small BGE embedding family alone does not explain
the difference. No Basic Memory source code is incorporated here.
